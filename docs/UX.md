# AnoWorld 用户体验预览

本文描述**用户看见和做什么**，不是实现细节。数据落点对照 [Core.md](./Core.md)、[MainBeat.md](./MainBeat.md)。功能设计变更时同步改本文，避免体验和 schema 各说各话。

界面文案不出现 Beat、Edge、Transition 等内部词。对用户说：作品、设定、角色、情节、场景、对白、选项。

## 结论：schema 不该由用户填

以现在的 schema，一份**能开玩**的作品，系统里至少要有：

| 系统里有什么 | 玩家/作者要不要手填 | 三条路径里谁来补 |
| --- | --- | --- |
| 作品名 | 要，或从导入文件名带出 | 用户确认一下即可 |
| 文风预设 | 可不碰；没有就用内置默认 | 想换文风再改 |
| 世界观 / 设定 | 角色卡、小说里通常已有 | 路径 1/2 自动填；路径 3 用一句提示词生成 |
| 角色 | 同上 | 同上 |
| 主线概括 | 角色卡里往往**没有完整剧情** | 必须由 AI 从素材或提示词生成一段可玩开场 |
| 情节节点 + 场景对白 + 选项 | 用户不应从空白画布画起 | AI 生成短主线；用户只微调 |
| 图片 | 没有也能先玩（占位） | 生图或稍后导入，不挡「开始游玩」 |

所以：**对用户并不复杂，前提是入口是「导入 / 贴故事 / 分阶段提示词」，出口是「直接玩」，画布和逐字段编辑是事后微调。** 若第一步就是空节点编辑器，以现在的 schema 会显得太重——那不是目标体验。

角色卡本身通常只有人和设定，没有「节点 → 对白」这条可玩链。导入后软件要**自动再生成一小段开场**（几个情节、能点的选项），微调后才能立刻玩。只把世界书和人设填进去、不生成开场，VN 模式无内容可播。

---

## 共同壳：三条路之后长一样

无论从哪条路进来，用户落在同一个作品上，之后只有三件事：

1. **玩**：选聊天式或视觉小说式，从开场开始；能存档。
2. **改**：觉得不对，回到对应位置改一句设定、一段对白、一个选项，或让 AI 按这句话重写这一段。
3. **补画面**：玩的时候可以先是占位图；之后用生图或自己导入，绑到场景/角色上，再玩一遍即可看到。

玩和改之间随时切换，不必「做完一整本才允许玩」。

## 路径 1：导入酒馆角色卡

**用户想要的感觉**：选一个卡 → 看软件读懂了什么 → 改两句 → 开玩。

### 用户做的事

1. 选择角色卡文件（可多张：一张主卡 + 配角卡）。
2. 看一页「读到了这些」（设定、角色、示例对白、首句等），划掉不想要的，改错别字或不合流程的句子。
3. 点「生成开场并开始」。软件用读到的素材写一段短主线（默认很短：一两处场景、几句对白、两三个选项）。
4. 直接进入游玩。不满意再回来改设定、改对白，或让 AI 重写开场。

### 软件自动做的事

| 卡里常见内容 | 填到 |
| --- | --- |
| 世界书 / 情景 / 世界观类字段 | 作品设定 |
| 角色描述、性格、示例对话 | 对应角色 |
| 首条消息 | 开场对白的素材，并入生成出的第一场 |
| 正则、插件、酒馆预设文件 | 不导入 |

用户不连线、不建节点。生成结果在后台就是 Main 的节点和场景；预览里用「这一场 → 下一场」的列表给人看，需要时再打开情节图。

### 体验要点

- 确认页要短：每块设定可展开，默认只显示标题和一两行。
- 「生成开场」失败时留在确认页，说明缺的是文案 API，不要丢已读入的素材。
- 图可以后补；开场生成不强制等生图结束。

## 路径 2：导入小说或一段剧情

**用户想要的感觉**：贴上一段故事 → AI 拆成能玩的作品 → 开玩 → 哪段不对改哪段。

### 用户做的事

1. 新建作品，粘贴正文，或导入文本文件。可写一句补充（例如「只做到雨夜投宿为止」「主角是第一人称」）。
2. 等一页结果：设定摘要、登场角色、情节列表（每场一行标题 + 一句发生了什么）。
3. 可删掉某场、改标题，或点「按原文重写这一场」。
4. 点开始游玩。

### 软件自动做的事

从正文抽出并写入：设定、角色、主线概括、有序情节、每场对白和必要选项（原文没有分支时，生成少量合理选项，并保留一条「按原文继续」）。

长文不要一次吞完。体验上先做**用户划定的这一段**（或自动截成「第一章 / 前若干字」并告诉用户范围）。做完这一段能玩，再提供「继续根据后文生成下一场」。

### 体验要点

- 结果页先给人读「故事被拆成了哪几场」，不要先丢一张节点图。
- 和原文出入大时，用户能对单场重写，而不是整篇推倒。
- 同样允许无图开玩。

---

## 路径 3：从空白开始，分阶段写提示词

**用户想要的感觉**：每个阶段只写一两句人话，AI 生成这一阶段该有的东西，全程能玩，随时能改。

阶段固定、顺序建议如下（可跳过已满意的阶段）：

| 阶段 | 用户写什么 | 生成并填入 | 用户此时能做什么 |
| --- | --- | --- | --- |
| 1 世界 | 「雨夜的边城，人们靠传闻活着」 | 设定 | 改设定；还不能完整游玩 |
| 2 人物 | 「少年想离开，客栈老板知道出路」 | 角色 | 改人设；仍建议先有开场再玩 |
| 3 走向 | 「今晚必须出城，在客栈做一个选择」 | 主线概括 + 短情节 + 对白和选项 | **可以开始游玩** |
| 4 画面（可后做） | 「城门冷色、客栈暖色」或直接生图/导入 | 场景图、立绘 | 再玩时看到图 |

阶段 3 结束就是「能玩」的分界。阶段 1、2 的提示词要短；软件用内置默认文风，除非用户提前改了预设。

每一阶段都是：输入框 → 生成 → 就地预览可编辑文本 → 下一步 / 重写这一阶段。不要在阶段 1 打开情节画布。

### 体验要点

- 提示词旁边给一句例子，不给 schema 说明。
- 「重写这一阶段」只动这一阶段的产物（改人物不默默删掉已经玩过的对白；若对白里用到被删角色，标出来让用户决定）。
- 和路径 1、2 一样，玩的时候发现问题，回到对应阶段或直接改那一场对白。

## 微调：三条路共用，而且是可选的

开玩之后，用户只会因为「这里不对」进来，而不是为了填满 schema。

| 用户觉得 | 打开的界面 | 背后改的数据 |
| --- | --- | --- |
| 人设/世界观偏了 | 设定或角色页 | Background / Cast |
| 这句话不对 | 这一场的对白 | 某个场景的 lines |
| 选项不想要 / 想多一个走向 | 这一场的选项 | choices |
| 前后场顺序不对 | 主线节点编辑器（全端同一套）；小屏可打开卡片模式沿连接跳转 | nodes / edges |
| 画风不对 | 文风预设，然后重写某一场 | Preset + 再生成 |
| 图不好看 | 这一场的图片：再生或换一张自己的 | 资源槽 |

情节图用来调整走向，不是三条创作入口的第一步。打开之后，手机、平板、桌面都是同一套节点编辑器。另有「小屏卡片」开关，见下一节。

---

## 和「会不会太复杂」的对照

| 如果体验是这样 | 复杂度 |
| --- | --- |
| 导入或几句提示词 → 确认摘要 → 开玩 → 哪里不对改哪里 | 符合这三条路径，schema 被藏住 |
| 先认识节点、边、节拍，再手写每一句并连线 | 对目标用户过重，不要作为默认 |

验收这三条路径时，用同一句话检查：**不打开情节图，能不能从导入或提示词玩到第一个选项？** 不能，就说明生成开场或阶段 3 没有成为默认，体验仍然太复杂。

## 主线节点编辑器：交互验收

创作入口仍不从空白画布开始。用户要改走向时，打开的是**同一套节点编辑器**，外加一个可选的小屏卡片模式。两种呈现读写同一份节点和连接；关掉卡片模式回到画布，图不丢、连线不变。

### A. 节点编辑器（默认，全端一致）

手机、平板、桌面都提供完整节点编辑器，不因「是移动端」换成另一套编辑器。平板按这套验收，不按小屏卡片验收。

| # | 验收 |
| --- | --- |
| A1 | 各端都能：平移画布、缩放、选中节点、拖动节点、从节点拉出连线到另一节点、删除节点、删除连线 |
| A2 | 点节点进入该节点里的场景与对白，不离开「这是同一张图」的关系 |
| A3 | 手机上的编辑器与桌面是同一套交互（触控代替鼠标），不是功能被砍掉的简化版 |
| A4 | 不依赖悬停才能完成选中、连线、删除 |
| A5 | 画布上看到的块和线 = 作品里的节点和连接；运行时走向与画布一致 |

### B. 小屏卡片（必须有的开关，默认关）

编辑器里有明确选项，例如「小屏卡片」。关闭时只有 A。开启后用卡片浏览同一张图，方便窄屏；桌面和平板也能打开，行为与手机相同。

静息：当前节点是一张卡，**水平居中**，连接列表不占屏。

```text
居中
        ┌─────────┐
        │  客栈    │
        └─────────┘

向左划（卡片左移，右半边空出）          向右划（卡片右移，左半边空出）
┌────                ┌──────────┐      ┌──────────┐                ────┐
│客栈 │   连出去的节点  │ 城门     │      │ 城门     │  连进来的节点   │客栈│
└────                └──────────┘      └──────────┘                ────┘
     只剩半张卡在屏内                      只剩半张卡在屏内
     另半张在屏幕外                        另半张在屏幕外
```

| # | 验收 |
| --- | --- |
| B1 | 开启后当前节点以卡片居中显示，能看出标题（及一句摘要，若有） |
| B2 | **向左划**：卡片只留大约一半在屏内，另一半在屏外；空出的那半屏列出**从这张卡连出去**的节点。没有连出时，这半屏是空状态，而不是空白错位 |
| B3 | **向右划**：对称。空出的那半屏列出**连进这张卡**的节点 |
| B4 | 半屏里每一条连接可点；点中后，那张被连到的卡成为当前卡，并回到居中 |
| B5 | 多条连接在半屏里可滚动点选；点哪条打开哪张，不跳错 |
| B6 | 反向滑回，或点仍露在屏内的半张卡，回到居中，**不换**当前节点 |
| B7 | 左右滑动只移动卡片，不触发系统返回、不翻到别的页面 |
| B8 | 关闭开关后回到节点编辑器，节点位置与连接与开启前一致 |
| B9 | 卡片模式不维护第二份剧情；它只是小屏下看连接、跳到相邻节点的方式 |

点居中的卡片，仍进入该节点的场景与对白（与 A2 相同）。增删节点、改连线在节点编辑器里完成；卡片模式的本项验收是浏览和沿连接跳转。
