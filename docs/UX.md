# AnoWorld 用户体验预览

本文描述**用户看见和做什么**，不是实现细节。数据落点对照 [Core.md](./Core.md)、[MainBeat.md](./MainBeat.md)。功能设计变更时同步改本文，避免体验和 schema 各说各话。

界面文案必须面向用户：短、口语、说清能做什么；不出现 Beat、Edge、Transition、schema、token、NativeTavern、LLM、「接入」等内部词或注释口吻。副标题/说明行简明扼要、不说教，末尾不加句号。对用户说：作品、设定、角色、情节、场景、对白、选项。技术设置用通俗标签（服务地址、密钥）。更细约定见 `.cursor/rules/ui-copy.mdc`。

## 游玩体验目标（先记住这个）

像带剧情大纲的 Gal / SLG：

- **有脉络**：故事大站、分支、可能的结局在创作时已经定好（情节图上的大节点和连线）。
- **有选择**：玩家在游玩中做选择，可能走进不同分支、到达不同结局。
- **站与站之间很活**：两个大情节之间的过程，由 AI **当场生成**（对白、小互动），自由发挥。
- **但不能玩飞**：系统要保证总能接到「下一站情节」或合法结局；跑偏可重来，并始终有「前往下一情节」之类的稳妥出口。

创作入口仍然是「导入 / 贴故事 / 几句提示词」，不是先教用户画节点。生成出来的首先是**脉络**（概括 + 大站 + 分支）；开玩后才在站与站之间实时填戏。对照数据层见 [Core.md](./Core.md)。

---

## 结论：schema 不该由用户填

一份**能开玩**的作品，系统里至少要有：

| 系统里有什么 | 玩家/作者要不要手填 | 三条路径里谁来补 |
| --- | --- | --- |
| 作品名 | 要，或从导入文件名带出 | 用户确认一下即可 |
| 文风预设 | 可不碰；没有就用内置默认 | 想换文风再改 |
| 世界观 / 设定 | 角色卡、小说里通常已有 | 路径 1/2 自动填；路径 3 用一句提示词生成 |
| 角色 | 同上 | 同上 |
| 主线概括 + 大情节站 + 分支 | 角色卡里往往没有完整剧情树 | AI 从素材或提示词生成**脉络骨架**；用户可微调站名/走向 |
| 站与站之间的对白过程 | 用户不应手写整本 | **游玩时 AI 实时生成**（可预写开场钩子，非必须） |
| 图片 | 没有也能先玩（占位） | 生图或稍后导入，不挡「开始游玩」 |

所以：**对用户并不复杂——入口是导入或提示词，出口是直接玩；情节图用来事后改大走向，不是第一步。** 用户看到的「能玩」，靠的是「骨架已就绪 + 游玩时 AI 能演下去」，不是创作时写满每一句。

角色卡通常只有人和设定。导入后软件要生成**可玩脉络**（若干大站与至少一处分支/结局出口）；第一站可以立刻开玩，过程戏现场生成。只填人设不生成脉络，则没有「下一站」可收敛。

## 共同壳：三条路之后长一样

无论从哪条路进来，用户落在同一个作品上，之后只有三件事：

1. **玩**：选聊天式或视觉小说式；沿大情节推进；站与站之间看 AI 演；关键岔口做选择；能存档。
2. **改**：觉得不对，改设定/角色、改某站目标或分支，或让 AI 重写脉络/重来某一段过程。
3. **补画面**：可先占位；再生图或导入，绑到场景/角色上。

玩和改之间随时切换，不必「写完每一句才允许玩」。

## 设置（从首页顶栏进入）

首页本身没有底栏。进入设置后才有分区导航（窄屏为悬浮胶囊底栏 / 宽屏侧栏）：**通用** / **外观** / **AI** / **关于**。

- **外观**：主题模式（跟随系统/浅/深）；主题预设 / 自定义颜色 / 字体等均用同一套浮层抽屉（两侧内缩、限宽，列表类默认半屏）；主题预设行尾显示当前包名；自定义颜色含「保存为主题」「恢复默认」；字体可选系统默认 / 本机 / 导入；字体大小/圆角滑块。各项列表与滑块左侧有图标。改完立即作用到全局封装控件。视觉约定见 [Style.md](./Style.md)。
- **AI**：写故事与生图分开选服务商（半屏浮层抽屉，标题与说明固定不随列表滚）。各自填写服务地址、密钥；切换服务商会记住上次内容。能自动查找模型的，填好后会拉出列表；点模型即可选用，也可点「查找模型」。
- **关于**：应用图标与一句话说明。

## 路径 1：导入酒馆角色卡

**用户想要的感觉**：选一个卡 → 看软件读懂了什么 → 改两句 → 开玩。

### 用户做的事

1. 选择角色卡文件（可多张：一张主卡 + 配角卡）。
2. 看一页「读到了这些」（设定、角色、示例对白、首句等），划掉不想要的，改错别字或不合流程的句子。
3. 点「生成脉络并开始」。软件用读到的素材写出短主线**骨架**（默认：若干大情节站、站目标一句话、至少一处分支或结局出口；不必写满对白）。
4. 直接进入游玩：第一站起由 AI 演过程；不满意再回来改设定、改某站目标，或让 AI 重滚脉络。

### 软件自动做的事

| 卡里常见内容 | 填到 |
| --- | --- |
| 世界书 / 情景 / 世界观类字段 | 作品设定 |
| 角色描述、性格、示例对话 | 对应角色 |
| 首条消息 | 开场素材，供第一站区间 AI 使用 |
| 正则、插件、酒馆预设文件 | 不导入 |

用户不连线、不建节点。生成结果在后台是 Main 的节点与连线；预览用「这一站 → 下一站」列表；需要时再打开情节图。

### 体验要点

- 确认页要短：每块设定可展开，默认只显示标题和一两行。
- 「生成脉络」失败时留在确认页，说明缺的是文案服务，不要丢已读入的素材。
- 图可以后补；不强制等生图结束。

## 路径 2：导入小说或一段剧情

**用户想要的感觉**：贴上一段故事 → AI 拆成能玩的作品 → 开玩 → 哪段不对改哪段。

### 用户做的事

1. 新建作品，粘贴正文，或导入文本文件。可写一句补充（例如「只做到雨夜投宿为止」「主角是第一人称」）。
2. 等一页结果：设定摘要、登场角色、情节列表（每场一行标题 + 一句发生了什么）。
3. 可删掉某场、改标题，或点「按原文重写这一场」。
4. 点开始游玩。

### 软件自动做的事

从正文抽出并写入：设定、角色、主线概括、**有序大情节站（含一句话目标）与分支**；原文没有分支时，补少量合理岔路并保留「按原文继续」类走向。对白过程留给游玩时 AI（可选预写第一站钩子）。

长文不要一次吞完。体验上先做**用户划定的这一段**（或自动截成「第一章 / 前若干字」并告诉用户范围）。这一段的骨架能玩后，再提供「根据后文续接下一站」。

### 体验要点

- 结果页先给人读「故事被拆成了哪几站」，不要先丢一张节点图。
- 和原文出入大时，用户能对单站重写目标/重滚，而不是整篇推倒。
- 同样允许无图开玩。

## 路径 3：从空白开始，分阶段写提示词

**入口已接通**（路径 1 / 2 仍为占位）：首页「分阶段提示词」→ [`StagedCreatePage`](../lib/create/staged_create_page.dart)。需在设置 → AI 配好写故事服务（[`OpenAiChatClient`](../lib/foundation/ai/openai_chat_client.dart) + [`StagedCreateActions`](../lib/domain/ai/staged_create_actions.dart)）。

**目标体验**：每个阶段只写一两句人话；阶段 3 产出的是**脉络骨架**（概括 + 大站 + 分支），开玩后站间由 AI 实时演。

| 阶段 | 用户写什么 | 生成并填入（目标） | 用户此时能做什么 |
| --- | --- | --- | --- |
| 1 世界 | 「雨夜的边城，人们靠传闻活着」 | 设定 | 改设定；还不能完整游玩 |
| 2 人物 | 「少年想离开，客栈老板知道出路」 | 角色 | 改人设；仍建议先有脉络再玩 |
| 3 走向 | 「今晚必须出城，在客栈做一个选择」 | 主线概括 + **大情节站（含目标）+ 分支/结局出口** | **可以开始游玩**（过程戏现场生成） |
| 4 画面（可后做） | 「城门冷色、客栈暖色」或直接生图/导入 | 场景图、立绘 | 再玩时看到图（本阶段尚未做） |

阶段 3 结束就是「能玩」的分界：骨架合法且文案服务可用即可开玩，**不要求**创作时写满对白。

**当前实现**：路径 3「走向」只生成 `summary` + 大站（含 `synopsis`）+ `default`/`branch` 边（`beats` 可空）；作品页「继续创作」打开创作截面（文风 / 设定 / 角色 / 情节）；游玩时空拍进 [`BridgeGenerateAction`](../lib/domain/ai/bridge_generate_action.dart)，失败或未配文案服务时用「前往：{下一站}」保底；样例「雨夜投宿」仍带预写对白作静态对照。路径 1/2、阶段 4 生图未做。

每一阶段：输入框 → 生成 → 就地预览可编辑 → 下一步 / 重写。不要在阶段 1 打开情节画布。未配置文案服务时留在当前阶段提示去设置，不丢已写入内容。

### 体验要点

- 提示词旁边给一句例子；预览讲「有哪几站、怎么分支」，不要堆内部字段名。
- 「重写这一阶段」只动这一阶段产物（改人物不默默拆掉已生成的脉络；冲突时标出来让用户决定——待补）。
- 游玩中过程不对：可「重来这一段」或改站目标后再玩；大走向不对：回情节图或重滚阶段 3。

## 创作截面（作品内）

作品页点「继续创作」进入 [`CreateHubPage`](../lib/create/create_hub_page.dart)：四条入口，点进各自编辑页。

| 入口 | 用户在改什么 | 编辑页 |
| --- | --- | --- |
| 文风预设 | 怎么写、不要写什么、更想要什么；可多套切换 | [`PresetEditorPage`](../lib/create/preset_editor_page.dart) |
| 背景设定 | 世界事实条目：常驻或关键词唤起 | [`BackgroundEditorPage`](../lib/create/background_editor_page.dart) |
| 角色 | 姓名、简介、性格、说话方式、示例对白 | [`CastEditorPage`](../lib/create/cast_editor_page.dart) |
| 情节走向 | 大站与分支（原节点画布） | [`MainGraphPage`](../lib/create/main_graph/main_graph_page.dart) |

副标题用当前作品摘要（套数/条数/人数/站数），不堆内部字段名。情节图仍只服务大走向，不是创作入口的第一步。

## 微调：三条路共用，而且是可选的

开玩之后，用户只会因为「这里不对」进来，而不是为了填满 schema。

| 用户觉得 | 打开的界面 | 背后改的数据 |
| --- | --- | --- |
| 人设/世界观偏了 | 创作截面 → 背景设定 / 角色 | Background / Cast |
| 这一站目标不对 / 分支不对 | 创作截面 → 情节走向 | nodes / edges / synopsis |
| 过程戏这段不对 | 游玩中「重来这一段」或创作里预写钩子 | 区间会话 / 可选预写 Beats |
| 想多一个结局或岔路 | 创作截面 → 情节走向 | nodes / edges |
| 画风不对 | 创作截面 → 文风预设 | Preset |
| 图不好看 | 图片：再生或换自己的 | 资源槽 |

全端同一套节点编辑器；底栏可切「画布 / 卡片」，见下一节。

## 游玩中：选择、分支与「别玩飞」

玩家在 VN / 聊天里应感到：

1. 知道自己大致在故事的哪一站（可用站标题，不必展示整张图）。
2. 过程里可以自由选、看 AI 演下去。
3. 关键岔口能选进不同大站或结局（对应创作时的分支）。
4. **总有稳妥出口**：例如「前往：客栈」——即使 AI 发挥跑偏，也能进到下一站情节，而不会卡在无法继续的胡话里。

失败与重试：生成失败提示检查文案服务；跑偏可「再写一段」；不要静默吞掉进度。

---

## 和「会不会太复杂」的对照

| 如果体验是这样 | 复杂度 |
| --- | --- |
| 导入或几句提示词 → 确认有几站/怎么分支 → 开玩（过程 AI 演）→ 哪里不对改哪站 | 符合目标，schema 被藏住 |
| 先认识节点、边、节拍，再手写每一句并连线 | 对目标用户过重，不要作为默认 |
| 开玩后 AI 完全自由聊，聊到接不上任何下一站 | 失败；缺少收敛 |

验收创作入口时检查：**不打开情节图，能不能从导入或提示词进入第一站并遇到可点的选项（含通往下一站的稳妥出口）？**  
验收游玩时检查：**选完一条分支后，是否进入了创作时定好的另一大站（或结局），而不是卡死或另起无关故事？**

## 主线节点编辑器：交互验收

创作入口仍不从空白画布开始。用户要改走向时，打开的是**同一套节点画布**，底部胶囊可切「卡片」视角。切换只改相机（居中放大当前站），不换另一套 UI；切回画布后自由平移/缩放恢复，图不丢、连线不变。

### A. 节点编辑器（默认，全端一致）

手机、平板、桌面都提供完整节点编辑器，不因「是移动端」换成另一套编辑器。平板按这套验收，不按卡片视角验收。

| # | 验收 |
| --- | --- |
| A1 | 各端都能：平移画布、缩放、选中节点、拖动节点；节点色条为站名、内容区左右插头带说明（进入 / 继续·岔路·添加）；右侧出线标题可点开编辑标题与详细说明，并可让 AI 展开；拖插头到另一站左侧连线；连线可点选（高亮线与两端插头）；与「情节走向」标题同行右侧（由右向左）圆形「更多」「重做」「撤销」（与返回同大；不可用时灰掉；桌面 Cmd/Ctrl+Z、Shift+Z / Ctrl+Y）；「更多」打开抽屉可开「显示网格」（LOD 间距，缩放仍疏密舒适）；画布右下角圆形图标钮「整理排版」「加一站」；拖节点整段算一步撤销；整理排版按站关系从左到右分层重排（覆盖当前坐标）；删线在边的编辑浮层里 |
| A2 | 选中节点后，节点上方出现圆形「复制」「编辑」「删除」图标钮（相对节点定位，拖到画布上沿以外仍贴在站顶上方）；编辑打开**按内容收高**的浮层，改站标题、本站目标、种类（开场/过程/转折/结束）与出边列表；复制生成错位的同内容新站（不带连线）；删除先弹出确认（画布按钮与浮层内「删除这一站」相同，仍可用撤销找回）；仅剩一站时不显示删除；本阶段不进完整对白表单（对白归区间 AI） |
| A3 | 手机上的编辑器与桌面是同一套交互（触控代替鼠标），不是功能被砍掉的简化版 |
| A4 | 不依赖悬停才能完成选中、连线、删除 |
| A5 | 画布上看到的块和线 = 作品里的节点和连接；运行时走向与画布一致 |

### B. 卡片视角（底栏切换，默认画布）

编辑器底部有与设置同款的悬浮胶囊导航：**画布** / **卡片**（默认「画布」）。选「卡片」后**仍是同一张画布**：相机把当前选中站缩放到视口中央并适当放大，方便窄屏看清这一站；桌面和平板也能用，行为与手机相同。

```text
画布                             卡片（同一画布）
┌────────────────────┐          ┌────────────────────┐
│  ○──○──○           │   →      │                    │
│     └─○            │          │      ┌──────┐      │
│                    │          │      │ 客栈  │      │
│   [画布] [卡片]    │          │   [画布] [卡片]    │
└────────────────────┘          │      └──────┘      │
                                └────────────────────┘
```

| # | 验收 |
| --- | --- |
| B1 | 选「卡片」后仍渲染完整节点与连线（同一 `GraphViewport`）；当前站居中放大，相机动画到位 |
| B2 | 卡片期间禁用画布平移与双指缩放；点空白不取消选中，避免相机失焦 |
| B3 | 点另一站即选中并相机跟到该站；仍可拖动站、拖插头连线；选中后可用节点上方「复制 / 编辑 / 删除」（与 A2 相同） |
| B4 | 拖完当前站后相机会重新对准该站 |
| B5 | 切回「画布」后恢复自由平移/缩放；节点位置与连接与切换前一致（仅相机复位） |
| B6 | 卡片视角不维护第二份剧情；只是同一张图的聚焦视角 |
