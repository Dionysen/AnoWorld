# AnoWorld 内容核心模型

创作器产出、运行时消费的同一套内容分层。聊天式与 VN 式播放都挂在此模型上，只换 UI。

## 分层总览

```text
Project
├── Preset         文风 / 输出禁用 / 输出偏好等（借鉴酒馆预设，非兼容）
├── Background     世界观 / 基础设定（可扩展为世界书条目，待定）
├── Cast           角色
├── Main           主线概括 → 大节点与分支（画布）→（节点内）Beats
├── Side           支线定式 + 定式下的填槽发挥
└── Beats/Scenes   可运行最小单元（双模式共用；可创作预写，也可运行时由 AI 填）
```

依赖方向：Preset 约束「怎么写」；Background / Cast 支撑「写什么」；Main 的**节点与边**管「故事能走到哪」；Beat 才是屏幕上逐步演出的东西。

**产品形态（权威）**：接近 Galgame / SLG——**创作时定好剧情脉络与分支**，**节点与节点之间由 AI 实时发挥**，但必须**收敛**到下一主节点（或合法结局），不能把玩家带到无法接续主脉络的死角。详见下文 Main，以及 [MainBeat.md](./MainBeat.md)、[UX.md](./UX.md)。

**Main ↔ Beat 字段与推进规则**：见 [MainBeat.md](./MainBeat.md)（权威 schema）。

## Preset（预设）

- **是什么**：控制 AI **如何输出** 的可切换配置包，概念上参考酒馆「预设」，但只取 AnoWorld 需要的能力，不做 ST 预设文件/正则/提示词工程全兼容。
- **与 Background 的分工**：Background 是世界事实（写什么）；Preset 是表达与约束（怎么写、禁止写什么、偏好写什么）。二者不要混进同一文本堆。
- **典型内容（MVP 可先做结构化字段）**：

| 类别 | 示例 |
| --- | --- |
| 文风 | 叙述人称、语气、篇幅倾向、对白密度、文学/白话等 |
| 输出禁用 | 禁止的内容类型、剧透、OOC、系统腔、特定词汇/桥段等 |
| 输出偏好 | 偏好细节方向、选项风格、是否先给摘要再展开、格式约定等 |
| 作用范围 | 绑定「创作器 AI 动作」和/或「运行时聊天续写」；可设项目默认预设 |

- **形态**：项目内可存多套预设，当前启用一套；可复制、改名、导出/导入（AnoWorld 自有格式即可）。
- **不做**：ST 式复杂提示词拼接脚本、正则替换链、第三方预设格式 1:1 导入（若日后要「从酒馆预设摘取文案」再单开，默认可手建）。

## Background（背景）

- **是什么**：最宏大也最基础的设定——时代、势力、规则、基调、不可轻易打破的事实。
- **MVP**：以结构化文本块为主（可分节：世界观、地理、规则、禁忌等），供创作与 AI 动作注入上下文。
- **世界书（待定）**：可借鉴 ST「条目 + 触发/检索」思路，把长设定拆成可检索条目，控制运行时/续写时的上下文体积。  
  - MVP 可不做完整世界书引擎。  
  - 若做最小版：条目 = 标题 + 正文 + 简单启用条件（如关键字 / 绑定章节），不做正则与复杂优先级。

## Cast（角色）

- 姓名、设定摘要、性格、对白风格、示例对白、立绘/头像资源引用等。
- 来源：手建，或从 ST 角色卡**选择性摘取**字段后映射至此（及必要的 Background 片段）。
- 立绘等图片：优先走**生图通道**配置的供应商（与文本/LLM 供应商列表分离，对齐 NativeTavern `ImageGenProvider`）；同时支持用户本地导入；运行时只认资源引用。
- 角色是素材与演出主体，不是 ST 运行时人格容器；无插件、无正则人格脚本。

## Main（主线）——脉络骨架 + 区间内 AI

体验对标：有清晰大纲与分支的 Gal / SLG——**大走向是定好的**，玩家选择走进不同分支、可能到达不同结局；**大节点之间的过程戏由 AI 实时生成**，自由发挥，但必须能回到主脉络上的下一站。

### 两层分工

| 层 | 何时定 | 是什么 | 不是什么 |
| --- | --- | --- | --- |
| **脉络骨架** | **创作时**生成/编辑并固化进作品包 | `summary`、大节点（标题 + 本站目标 `synopsis`）、`edges`（顺序 / 分支 / 汇合）、通往各结局的出口 | 不是逐句剧本；不是玩家当场发明新的主节点 |
| **区间发挥** | **游玩时**在「当前主节点 → 下一合法主节点」之间实时生成 | 若干 Beat：场景感、对白、过程选项；文风受 Preset 约束 | 不得改写骨架上的节点集合；不得把故事写到无法接续任一合法下一节点 |

```text
创作时：  summary + nodes(+synopsis) + edges(+结局出口)
              │
游玩时：  进入节点 A ──AI 实时生成区间 Beats──▶ 收敛到 edge 指向的 B / 结局
              │                      ▲
              │                      └── 选项与续写必须朝向「完成本站目标 / 进入合法下一站」
```

### 骨架字段（创作）

- **主线概括 `summary`**：整段故事的目标、冲突、可能结局方向（给作者与 AI 用，不是逐句剧本）。
- **节点（大情节单元）**：里程碑式「这一步故事要发生什么」；`synopsis` = 本站必须达成或抵达的剧情目标（运行时 AI 的收敛锚点）。节点之间的流向（顺序、分支、汇合）在**主线节点编辑器**表达。
- **粒度**：节点是情节级大站，不是每一句对白一个节点；句段级内容落在 Beat。
- **分支与结局**：用 `edges` / 节点出口表达多路线；玩家选择最终应对齐到某条合法边或 `end`，从而可能达成不同结局。
- **编辑 UX**：全端同一套节点编辑器；可选小屏卡片。验收见 [UX.md](./UX.md)。
- **预写 Beat（可选）**：作者或创作 AI 可预写某节点内的开场钩子；**默认允许节点在创作结束时 Beat 仍为空**，交给游玩时 AI 填（校验规则见 MainBeat）。

### 区间 AI（游玩）

- 玩家处在某主节点的「发挥区间」：已知本站 `synopsis`、可用的下一跳（出边）、Background / Cast / Preset、近期游玩摘要。
- AI **实时**生成对白与过程选项（VN 舞台与聊天气泡共用同一推进）；过程选项可暂时只在区间内打转，但系统必须保证存在**收敛通路**（见下）。
- **进入下一主节点**：当区间收敛完成（本站目标满足 / 玩家点了导向某出边的关键选项），指针跳到 `edge.to`（或结局），再开新区间。
- **禁止**：运行时 AI 擅自增删主节点、发明骨架上不存在的结局、写出与所有合法下一站 `synopsis` 都矛盾且无法挽回的死局。

### 收敛（硬约束）

「自由发挥」不等于「无限跑偏」。产品要求：

1. **下一站集合封闭**：区间结束时只能进入创作时已存在的邻接节点或声明的结局。
2. **目标锚定**：生成与选项文案须服务「完成本站 synopsis，并自然接到某一合法下一站」。
3. **失败可拉回**：若模型跑偏，运行时丢弃该段或要求重写，并提供「推进到下一情节」类保底选项（指向合法出边），避免卡死。
4. **有限回合（建议）**：单区间 AI 拍数或选项轮次设上限，到期强制给出收敛选项。

字段级推进与存档见 [MainBeat.md](./MainBeat.md)。资源：场景图等仍以生图或导入挂槽；无图可先玩。

## Side（支线）

- **可拼装**：支线是可插入主线缝隙的模块，不强制改写主线骨架。
- **定式**：可复用的叙事模板（如偶遇、冲突、交易、告白），带槽位（参与角色、地点、冲突、奖励/后果）。
- **定式下的自由发挥**：同一模板由作者或 AI 填槽生成具体 Beats；模板稳定，实例可再编辑。与「主线区间 AI」类似，但挂在支线实例上，仍不得破坏主脉络合法出口。
- MVP：先支持少量内置定式 + 生成/手改一集支线，再谈定式市场或复杂编排。

## Beat / Scene（可运行单元）

双模式共用的最小播放单位。来源可以是**创作预写**或**游玩时 AI 写入（可只进存档会话，不必改作品包）**。字段与推进以 [MainBeat.md](./MainBeat.md) 为准；摘要如下：

| 概念 | 说明 |
| --- | --- |
| 所属 | 某主线 **Node**（或日后支线实例） |
| 场景 | `backgroundAssetId`、地点文案 |
| 出场 | 角色 + 立绘/表情/站位 |
| 对白 | `lines[]`（说话人 + 文本） |
| 选项 | `choices[]` → `Transition`（beat / node / end）；区间 AI 的关键收敛选项应落到合法 `node` / `end` |
| 无选项 | 下一 Beat → 否则按收敛规则给出下一主节点 / end |

- **VN 模式**：舞台化展示；区间内容可边生成边播。
- **聊天模式**：同一指针与选项；气泡呈现；续写 = 同一套区间 AI，不得另起一套剧情树。

## 创作器 vs 运行时（内容视角）

| | 创作器 | 运行时 |
| --- | --- | --- |
| 读写 | 读写设定 / 角色 / **脉络骨架**（及可选预写 Beat）、定式、预设 | 只读骨架 + 设定；写进度 / 存档；**可写本局区间 AI 产生的临时 Beats** |
| AI | 生成世界观、角色、**主线节点与分支骨架**、润色；不负责整本逐句定稿 | **节点区间内实时生成与衔接**（Preset + Background + 本站/下一站 synopsis）；必须收敛 |
| ST | 仅角色卡等素材摘取 | 不出现 |

## 设计原则

1. **一份内容，两种皮肤**：禁止聊天轨与 VN 轨维护两套互不相干的剧本。
2. **脉络先于发挥**：先稳定 Background / Main 骨架（节点与分支），再在游玩（或预写）中填 Beats。
3. **骨架封闭、区间开放**：玩家选择改变的是「走哪条已有分支」，不是「AI 另造主线地图」。
4. **自由发挥必须收敛**：区间 AI 可以花，但不能堵死通往下一主节点或合法结局的路。
5. **定式可复用，实例可覆盖**：Side 模板不直接等于最终对白。
6. **设定与文风分离**：事实进 Background；文风/禁用/偏好进 Preset。
7. **预设可切换、可复用**：换预设改变发挥口吻，不改节点图。
8. **按需扩展**：字段与层服务当前闭环；不为兼容 ST 预留空抽象。
