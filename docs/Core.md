# AnoWorld 内容核心模型

创作器产出、运行时消费的同一套内容分层。聊天式与 VN 式播放都挂在此模型上，只换 UI。

## 分层总览

```text
Project
├── Preset         文风 / 输出禁用 / 输出偏好等（借鉴酒馆预设，非兼容）
├── Background     世界观 / 基础设定（可扩展为世界书条目，待定）
├── Cast           角色
├── Main           主线概括 → 节点（画布）→ Beats
├── Side           支线定式 + 定式下的填槽发挥
└── Beats/Scenes   可运行最小单元（双模式共用；挂在节点下）
```

依赖方向：Preset 约束「怎么写」；Background / Cast 支撑「写什么」；Main / Side 组织剧情；Beat 才是运行时逐步执行的东西。

**Main ↔ Beat 字段与推进规则**：见 [MainBeat.md](./MainBeat.md)（权威 schema）。

## Preset（预设）

- **是什么**：控制 AI **如何输出** 的可切换配置包，概念上参考酒馆「预设」，但只取 AnoWorld 需要的能力，不做 ST 预设文件/正则/提示词工程全兼容。
- **与 Background 的分工**：Background 是世界事实（写什么）；Preset 是表达与约束（怎么写、禁止写什么、偏好写什么）。二者不要混进同一文本堆。
- **典型内容（MVP 可先做结构化字段）**：

| 类别 | 示例 |
| --- | --- |
| 文风 | 叙述人称、语气、篇幅倾向、对白密度、文学/白话等 |
| 输出禁用 | 禁止的内容类型、剧透、OOC、系统腔、特定词汇/桥段等 |
| 输出偏好 | 偏好细节方向、选项风格、是否先给摘要再展开、格式约定等 |
| 作用范围 | 绑定「创作器 AI 动作」和/或「运行时聊天续写」；可设项目默认预设 |

- **形态**：项目内可存多套预设，当前启用一套；可复制、改名、导出/导入（AnoWorld 自有格式即可）。
- **不做**：ST 式复杂提示词拼接脚本、正则替换链、第三方预设格式 1:1 导入（若日后要「从酒馆预设摘取文案」再单开，默认可手建）。

## Background（背景）

- **是什么**：最宏大也最基础的设定——时代、势力、规则、基调、不可轻易打破的事实。
- **MVP**：以结构化文本块为主（可分节：世界观、地理、规则、禁忌等），供创作与 AI 动作注入上下文。
- **世界书（待定）**：可借鉴 ST「条目 + 触发/检索」思路，把长设定拆成可检索条目，控制运行时/续写时的上下文体积。  
  - MVP 可不做完整世界书引擎。  
  - 若做最小版：条目 = 标题 + 正文 + 简单启用条件（如关键字 / 绑定章节），不做正则与复杂优先级。

## Cast（角色）

- 姓名、设定摘要、性格、对白风格、示例对白、立绘/头像资源引用等。
- 来源：手建，或从 ST 角色卡**选择性摘取**字段后映射至此（及必要的 Background 片段）。
- 立绘等图片：优先走**生图通道**配置的供应商（与文本/LLM 供应商列表分离，对齐 NativeTavern `ImageGenProvider`）；同时支持用户本地导入；运行时只认资源引用。
- 角色是素材与演出主体，不是 ST 运行时人格容器；无插件、无正则人格脚本。

## Main（主线）

- **主线概括**：整段故事的目标、冲突、结局方向（给作者与 AI 用的大纲，不是逐句剧本）。
- **节点（情节单元）**：由概括拆出的可编排单元（场景块 / 关键情节点）；带目标说明，并下属若干 Beats。节点之间的流向（顺序、分支、汇合）在**主线重大界面用节点编辑器**表达。
- **粒度**：节点是情节级，不是每一句对白一个节点；句段级内容落在 Beat，避免主线画布过碎（尤其不利于移动端）。
- **编辑 UX**：手机、平板、桌面都是同一套节点编辑器（平移、缩放、拖节点、拉连线）。另有可关闭的「小屏卡片」：卡片居中，向左/右滑让卡片只露一半，空出的半屏列出该侧连接，点连接跳到那张卡。验收见 [UX.md](./UX.md)。
- 运行时进度沿主线节点 → Beat 推进；存档记录节点 / Beat 位置与必要状态。
- 资源：场景图等以 AI 生成为主，用户亦可本地导入，统一挂到节点/Beat 的资源槽。

## Side（支线）

- **可拼装**：支线是可插入主线缝隙的模块，不强制改写主线骨架。
- **定式**：可复用的叙事模板（如偶遇、冲突、交易、告白），带槽位（参与角色、地点、冲突、奖励/后果）。
- **定式下的自由发挥**：同一模板由作者或 AI 填槽生成具体 Beats；模板稳定，实例可再编辑。
- MVP：先支持少量内置定式 + 生成/手改一集支线，再谈定式市场或复杂编排。

## Beat / Scene（可运行单元）

双模式共用的最小播放单位。主线下的字段、跳转与默认推进以 [MainBeat.md](./MainBeat.md) 为准；摘要如下：

| 概念 | 说明 |
| --- | --- |
| 所属 | 某主线 **Node**（或日后支线实例） |
| 场景 | `backgroundAssetId`、地点文案 |
| 出场 | 角色 + 立绘/表情/站位 |
| 对白 | `lines[]`（说话人 + 文本） |
| 选项 | `choices[]` → `Transition`（beat / node / end） |
| 无选项 | 下一 Beat → 否则节点 `default` Edge → 否则 end |

- **VN 模式**：按 Beat 舞台化展示场景、立绘、对白、选项。
- **聊天模式**：同一指针与选项；气泡呈现；续写仍绑定当前节点上下文。

## 创作器 vs 运行时（内容视角）

| | 创作器 | 运行时 |
| --- | --- | --- |
| 读写 | 读写全部层，含草稿、定式、预设 | 只读可运行内容 + 当前预设约束；写进度/存档 |
| AI | 结构化生成/润色动作（注入当前 Preset） | 可选：聊天续写（Preset + Background/章节约束） |
| ST | 仅角色卡等素材摘取 | 不出现 |

## 设计原则

1. **一份内容，两种皮肤**：禁止聊天轨与 VN 轨维护两套互不相干的剧本。
2. **大纲先于正文**：Background / Main 概括稳定后，再生成或手写 Beats。
3. **定式可复用，实例可覆盖**：Side 模板不直接等于最终对白。
4. **设定与文风分离**：事实进 Background；文风/禁用/偏好进 Preset；世界书若引入，以可控检索为目的，不为兼容 ST。
5. **预设可切换、可复用**：同一项目可换预设验不同文风，而不改剧情骨架。
6. **按需扩展**：字段与层只服务当前 MVP 闭环，不为「将来可能像 ST」预留空抽象。
