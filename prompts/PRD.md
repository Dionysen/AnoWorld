# AnoWorld PRD（MVP）

## 一句话

AnoWorld 是用 Flutter 做的**视觉小说创作器 + 运行时**：在酒馆式 **AI 预设 / 提示词 / 玩家 Persona / 宏变量**之上，增加 **情节走向控制** 与更细的 **多角色设定（含配角）** 与世界书式背景；本地配置 AI API；创作时定 Gal/SLG 式脉络，游玩时站间 AI 发挥并收敛；双模式共用状态。ST 角色卡作素材入口；**预设与 Persona、宏语义**对齐 ST/NativeTavern，行为不要求整站克隆。

## 目标与非目标

### 目标

- 服务「爱玩又愿意创作」的用户：创作与游玩同等重要；不愿创作的也可导入现成包直接玩。
- 快速从设定落到**可玩脉络**（创作骨架 → 双模式游玩含站间 AI → 存读档）；或导入成品直接进入运行时。
- 游玩体验接近带大纲的 Gal / SLG：大走向清晰、玩家可分支、可多结局；站与站之间过程戏由 AI 现场生成，但不得玩到无法接续主脉络。
- 创作器与运行时职责分离；同一套内容模型驱动两种播放 UI。
- 跨平台（Windows / macOS / Linux / Android / iOS）一套代码，UI 视觉与交互一致（含移动端可用的主线节点编辑）。
- 可配置文本 AI 与生图 AI；创作侧用固定动作生成骨架/润色，运行侧用区间生成；图片以 AI 生成为主，并开放用户自行导入。
- 可选择性摘取 ST 角色卡字段，转为 AnoWorld 素材后二次创作；也可纯手建。

### 非目标（明确不做）

- 不做 SillyTavern **整站**替代品（无插件市场、无正则链、无扩展脚本宿主）。
- **要做（对齐 ST/NT）**：AiPreset 文件兼容、提示词管理、Persona、`{{…}}` 宏与变量展开（对照 `MacroService`）。
- 不做完整世界书 **正则 Key / 多层递归 / Sticky** 等引擎（故事内世界书见 Core）；不做正则、插件。
- 不做云同步、内容商店、账号体系（导入/导出本地包即可支撑「现成游玩」的第一版）。
- 不做 Live2D 等重资源管线（后续再议）。
- 不做「一个万能 AI 聊天框写完全稿 / 另造主线地图」；创作 AI 出骨架，游玩 AI 只在封闭出边内发挥。
- 不做桌面端专用的复杂节点 IDE；节点编辑必须在手机上也好用，桌面与移动共用同一套交互语言。

## 产品形态

| 层 | 职责 |
| --- | --- |
| **创作器** | 项目管理、设定（世界书）与**多角色** Cast、**主线脉络**、可选预写钩子、支线定式、ST 素材摘取、AI 文/图辅助、资源导入 |
| **设置（全局）** | 文本/生图连接、**酒馆 AiPreset**、提示词管理、**Persona** |
| **运行时** | 聊天式 / VN 式播放、**节点区间 AI 生成与收敛**、存档/读档；只读故事骨架 + 写进度与本局会话 |

两者可同 App 内切换入口，但数据流与界面职责分开：创作改骨架与设定；运行读骨架、写进度，并在区间内写临时发挥。纯玩家路径：导入项目包 → 运行时，可不进创作器。

## 用户取向

- **创作型玩家**（核心）：边玩边改、用 AI 生成/调整脉络与文风，而不是手写整本对白。
- **纯游玩**：导入他人/自己事先准备好的 AnoWorld 包（含脉络骨架），直接双模式游玩（站间 AI 仍依赖玩家本机配置的文案服务）。
- 创作器与运行时权重对等，避免做成「只有作者才打开的 IDE」或「只有播放器」。
- 默认创作体验见 [docs/UX.md](../docs/UX.md)：三条入口都先生成**可玩脉络**，节点图只用于事后改大走向。用户不手填内部字段。

## 技术约束

- 语言 / 框架：Dart + Flutter。
- UI：各平台一致；业务页只用基础设施封装组件；样式来自主题。
- 分层：`presentation → domain → data`；可移植能力放基础设施目录，无业务命名渗入。
- 存储：MVP 本地优先（项目文件 / 本地库）；API Key 等敏感配置本地安全存放。
- 网络：用于用户配置的文本 AI / 生图 AI；核心游玩与本地导入包不依赖自建后端。

## 内容与播放（摘要）

详见 [docs/Core.md](../docs/Core.md)、[docs/MainBeat.md](../docs/MainBeat.md)。

- 内容分层：Background → Cast → Main → Side（定式）→ Beat/Scene；**全局 AiPreset**（设置）管采样与 ST 提示词。
- **AiPreset**：与 SillyTavern 预设 JSON **兼容**（对照 NativeTavern 实现）；故事包内不再存预设。
- **Main 两层**：创作时固化 `summary` + 大节点（`synopsis`）+ `edges`（分支/汇合/结局）；游玩时在节点区间内由 AI 生成 Beats，且只能收敛到已有出边或合法 `end`。
- 聊天式与 VN 式**共用指针、区间会话与 Transition**，只换呈现。

## 创作入口（体验）

三条路径细节与验收句见 [docs/UX.md](../docs/UX.md)。

1. **酒馆角色卡**：摘取设定与角色；再生成短脉络骨架后可玩（过程戏运行时生成）。
2. **小说或一段剧情**：抽出设定、角色与大站分支；过长文本按用户划定一段处理。
3. **空白故事**：分阶段短提示词（世界 → 人物 → 走向 → 画面可选）；「走向」产出脉络即可开玩。

之后改大走向用情节图或重滚阶段；改进程戏用「重来这一段」或预写钩子——而不是让用户填整份内部结构。

## 素材：SillyTavern 角色卡

- 支持常见角色卡 JSON（如 V2/V3）解析。
- 自动映射有效素材：世界书/情景类 → 设定，角色描述与示例对话 → 角色，首条消息 → 开场素材。
- 用户在确认页微调；不保证与 ST 原卡行为一致。正则、插件不导入；**酒馆预设**在设置中单独导入，不写入故事包。

## AI 辅助（创作动作 + 游玩区间）

### 创作时（结构化动作）

输入输出可进编辑器、可撤销、可再生成，例如：

- 从一句话生成 Background 大纲
- 从提示/素材生成 **Main 脉络**（概括、大节点 synopsis、分支与结局出口）
- 按支线定式生成一集支线骨架
- 润色设定 / 统一文风；可选为某站预写开场钩子

### 游玩时（区间实时生成）

- 在「当前大站 → 合法下一站」之间生成 Beats 与过程选项；注入 Preset、设定、本站/邻站目标。
- **收敛**：合法 Transition 集合封闭；有限拍数触顶；UI 保底「前往下一情节」；非法或跑偏可重试。
- 不是第二个无限聊天人格：禁止运行时增删主节点。

设置项：文本与生图使用**不同供应商列表**（对齐 NativeTavern：`LLMProvider` vs `ImageGenProvider`）。文本侧：OpenAI / DeepSeek / OpenRouter / 通义 / 硅基流动 / Moonshot / 智谱 / MiniMax / Ollama / 自定义；生图侧：OpenAI Images / OAI Chat 生图 / 硅基流动 / Pollinations / NovelAI / A1111 / ComfyUI / 自定义。各自一份 Base URL、Key、Model；支持探测的渠道在输入密钥后可拉 `/models`。参考实现见同级仓库 `NativeTavern`，规则见 `.cursor/rules/nativetavern-reference.mdc`。

**当前实现**：文本侧已接通 OpenAI 兼容 `chat/completions`；路径 1 角色卡映射到 Background / Cast；**全局 AiPreset UI 与拼装对照 NT 落地中**；创作截面为设定 / 角色 / 情节（[`MainGraphPage`](../lib/create/main_graph/main_graph_page.dart)）；游玩侧 [`BridgeGenerateAction`](../lib/domain/ai/bridge_generate_action.dart) + 保底「前往：下一站」，存档可附带本局 `BridgeSession`。路径 2、生图调用、路径 1 自动生成脉络尚未落地。

## 图片资源

- **主路径**：配置生图 AI，按场景/角色描述生成背景图、立绘等，写入项目资源并挂到 Beat/Cast。
- **并行路径**：用户从本地自行导入图片，绑定到同一资源槽。
- 两种来源对运行时无差别，均为项目内资源引用。

## 游玩模式

1. **聊天式**：气泡流、区间续写、可选回复；观感可参考常见聊天式演出，但状态机与 VN 相同（骨架节点 + 区间会话）。
2. **视觉小说式**：场景图、角色图、对白、选项；同一状态的舞台化呈现。

两者都要体现：大站脉络清晰、玩家可分支、站间 AI 发挥、收敛出口可见。

## 编辑器取向

- **故事内创作截面**为设定 / 角色 / 情节；**AiPreset** 在设置；**Main** 再用节点编辑器：节点 = 关键情节单元及其流向。手机、平板、桌面是同一套编辑器，交互一致。
- **画布 / 卡片**用编辑器底部胶囊导航切换（默认画布）：卡片仍是同一张画布，相机把当前选中站居中放大；切回画布恢复自由平移/缩放。细则与验收见 [docs/UX.md](../docs/UX.md)。
- 两种视角读写同一张图，不另起一套 UI。支线 / 对白详情用列表或表单；节点图只服务主线骨架。

## MVP 成功标准（闭环）

见下文「MVP 定义」；验收上至少同时打通：

1. **创作路径**：新建/导入入口 → 设定与角色 → **Main 脉络骨架（含至少一处分支或双结局出口）** → 开玩（站间 AI 能演并能收敛到下一站）→ 存读档；图可后补  
2. **游玩路径**：导入现成骨架包 → 不经创作即可双模式游玩（本机已配文案服务）→ 存读档  

## 待决（不阻塞文档收敛）

- 世界书：故事内设定条目（常驻 + 关键词）；不做 ST 完整 World Info 引擎——见 Core。
- 区间 AI 默认 `maxBridgeBeats`、保底按钮文案、是否允许把本局发挥「固化」进故事包。
- 纯静态包（关闭区间 AI、全预写 Beat）是否作为导出选项保留。
- MVP 生图：设置侧已拆分供应商；运行时先落地一种主流调用即可。

## MVP 定义与范围

**MVP = 能让目标用户走通「生成一条带分支的短脉络，玩过站间 AI 并到达某一结局 / 或导入别人的骨架包直接这样玩」的最小产品**，而不是功能清单缩略版。

### 必须有（建议纳入第一版可发布）

| 块 | 最小形态 |
| --- | --- |
| 项目 | 新建、打开、本地导出/导入包 |
| AiPreset（设置） | ST 兼容预设 + 提示词管理；应用后作用于全部文本 AI |
| Persona（设置） | 玩家身份；与 ST 相同宏与 persona 段 |
| 宏 / 变量 | 展开规则继承酒馆（实现 port `MacroService` / 变量） |
| Background / Cast | 设定条目（常驻/关键词）+ 角色编辑页；ST 卡选择性摘取 |
| Main 脉络 | 创作截面进入；生成/可编大节点与分支；全端节点编辑器 + 小屏卡片（验收见 UX） |
| 区间 AI | 游玩时在站间生成过程戏；合法出边封闭；拍数上限 + UI 保底前往下一站 |
| Beat | 预写或本局生成；对白/选项/资源槽；双模式共用 |
| AI 文配置 | 文本 API 配置 + 创作动作（至少：设定/角色/脉络） |
| AI 图 | 至少一种可配置生图 + 结果入库；同时支持本地选图导入 |
| 运行时 | VN + 聊天；存读档（含区间会话） |
| 纯玩 | 导入骨架包后可只进运行时 |

### 明确推迟（有了也不算 MVP 失败条件）

- 完整世界书引擎、云同步/商店、ST 预设/正则兼容
- 节点编辑的高级能力（自动布局算法、小地图复杂交互、多人协作）
- 多生图提供商全家桶、批量出图工作流、Live2D
- 支线定式市场、精致演出时间轴
- 把每一局 AI 发挥自动回写为正式故事剧本的完整工作流

### 难点（按风险）

1. **区间 AI 收敛**  
   既要「像 SLG 一样能自由玩过程」，又要保证总能接到下一主节点/结局。难点在提示约束、非法 Transition 过滤、触顶策略与 UI 保底，而不是多调几次温度。

2. **节点编辑器与小屏卡片**  
   全端同一套真节点画布；小屏卡片 = 聚焦相机，共图。验收见 UX A/B。

3. **一份内容、两种播放 + 骨架/会话分离**  
   故事包装骨架（+ 可选预写）；存档装指针与本局区间。VN 与聊天必须共状态机，禁止两套剧情。

4. **AI 文/图接入的稳定性与可替换**  
   用户自备 API，失败与格式漂移是常态。创作动作与区间生成都要结构化容错（见 foundation JSON 候选等）。

5. **Main 节点 vs Beat 粒度**  
   节点 = 大情节站（脉络）；Beat = 站内可播放句段（含 AI 发挥）。节点过细会毁移动端画布；过粗则分支失去意义。

6. **范围膨胀**  
   「参考酒馆」滑向插件/世界书，「节点编辑器」滑向蓝图 IDE，「区间 AI」滑向无约束角色扮演。用「必须有 / 推迟」与 Core 收敛原则砍范围。
