# AnoWorld PRD（MVP）

## 一句话

AnoWorld 是用 Flutter 做的**视觉小说创作器 + 运行时**：本地配置 AI API，结构化创作剧本，用聊天式 / 视觉小说式双模式验本与游玩。SillyTavern 角色卡仅作素材入口，不是兼容目标。

## 目标与非目标

### 目标

- 服务「爱玩又愿意创作」的用户：创作与游玩同等重要；不愿创作的也可导入现成包直接玩。
- 快速从设定落到可玩故事（创作 → 双模式播放 → 存读档）；或导入成品直接进入运行时。
- 创作器与运行时职责分离；同一套内容模型驱动两种播放 UI。
- 跨平台（Windows / macOS / Linux / Android / iOS）一套代码，UI 视觉与交互一致（含移动端可用的主线节点编辑）。
- 可配置文本 AI 与生图 AI；按固定创作动作辅助生成与润色；图片以 AI 生成为主，并开放用户自行导入。
- 可选择性摘取 ST 角色卡字段，转为 AnoWorld 素材后二次创作；也可纯手建。

### 非目标（明确不做）

- 不做 SillyTavern 替代品或行为兼容层。
- 不做正则、插件、ST 扩展脚本、完整世界书优先级引擎（世界书是否借鉴见 Core，MVP 待定）。
- 不做云同步、内容商店、账号体系（导入/导出本地包即可支撑「现成游玩」的第一版）。
- 不做 Live2D 等重资源管线（后续再议）。
- 不做「一个万能 AI 聊天框写完全稿」；AI 以结构化动作为主。
- 不做桌面端专用的复杂节点 IDE；节点编辑必须在手机上也好用，桌面与移动共用同一套交互语言。

## 产品形态

| 层 | 职责 |
| --- | --- |
| **创作器** | 项目管理、预设、设定与角色、主线节点编辑、支线/Beat、ST 素材摘取、AI 文/图辅助、资源导入 |
| **运行时** | 聊天式 / VN 式播放、存档/读档；只消费可运行内容，并受当前预设约束 |

两者可同 App 内切换入口，但数据流与界面职责分开：创作改内容，运行只读内容 + 写进度。纯玩家路径：导入项目包 → 运行时，可不进创作器。

## 用户取向

- **创作型玩家**（核心）：边玩边改、用 AI 补全、调主线节点与文风。
- **纯游玩**：导入他人/自己事先准备好的 AnoWorld 包（或从 ST 素材经最小转换后的可玩项目），直接双模式游玩。
- 创作器与运行时权重对等，避免做成「只有作者才打开的 IDE」或「只有播放器」。
- 默认创作体验见 [docs/UX.md](../docs/UX.md)：三条入口（角色卡 / 故事文本 / 分阶段提示词）都先生成可玩内容，节点图只用于事后微调。用户不手填 schema。

## 技术约束

- 语言 / 框架：Dart + Flutter。
- UI：各平台一致；业务页只用基础设施封装组件；样式来自主题。
- 分层：`presentation → domain → data`；可移植能力放基础设施目录，无业务命名渗入。
- 存储：MVP 本地优先（项目文件 / 本地库）；API Key 等敏感配置本地安全存放。
- 网络：用于用户配置的文本 AI / 生图 AI；核心游玩与本地导入包不依赖自建后端。

## 内容与播放（摘要）

详见 [docs/Core.md](../docs/Core.md)。

- 内容分层：Preset → Background → Cast → Main → Side（定式）→ Beat/Scene。
- Preset 管文风 / 输出禁用 / 输出偏好（借鉴酒馆预设思路，不做 ST 预设兼容）。
- Main ↔ Beat 契约见 [docs/MainBeat.md](../docs/MainBeat.md)：节点画布管情节流向，Beat 管可播放内容与选项跳转。
- 聊天式与 VN 式**共用 Beat 指针与 Transition**，只换呈现。

## 创作入口（体验）

三条路径细节与验收句见 [docs/UX.md](../docs/UX.md)。

1. **酒馆角色卡**：自动摘取设定与角色等到对应位置；不导入正则/插件。摘取后自动生成短开场，用户微调即可游玩。
2. **小说或一段剧情**：AI 生成设定、角色与可玩主线后直接游玩；过长文本按用户划定的一段处理，再续下一段。
3. **空白作品**：分阶段短提示词（世界 → 人物 → 走向 → 画面可选），走到「走向」即可游玩。

之后的问题都回到局部编辑或让 AI 重写该段，而不是重做整份 schema。

## 素材：SillyTavern 角色卡

- 支持常见角色卡 JSON（如 V2/V3）解析。
- 自动映射有效素材：世界书/情景类 → 设定，角色描述与示例对话 → 角色，首条消息 → 开场素材。
- 用户在确认页微调；不保证与 ST 原卡行为一致。正则、插件、酒馆预设文件不导入。

## AI 辅助（按动作，非闲聊）

MVP 优先固定动作（输入输出可进编辑器、可撤销、可再生成），例如：

- 从一句话生成 Background 大纲
- 从主线概括拆章节 / Beats
- 按支线定式生成一集支线
- 为某 Beat 生成选项与后果摘要
- 润色对白 / 统一文风

设置项：文本 / 生图各自的 API Base URL、Key、Model 等，可移植、可更换。文案生成与续写注入项目当前 **Preset**（文风、禁用、偏好），与 Background 分离。

## 图片资源

- **主路径**：配置生图 AI，按场景/角色描述生成背景图、立绘等，写入项目资源并挂到 Beat/Cast。
- **并行路径**：用户从本地自行导入图片，绑定到同一资源槽。
- 两种来源对运行时无差别，均为项目内资源引用。

## 游玩模式

1. **聊天式**：气泡流、续写、可选回复；交互参考 ST 观感，状态仍来自当前场景 + 历史 + 设定检索范围。
2. **视觉小说式**：场景图、角色图、对白、回复选项；同一状态的舞台化呈现。

## 编辑器取向

- **Main 主线的重大界面使用节点编辑器**：节点 = 关键情节单元及其流向；点进节点再编辑下属内容。手机、平板、桌面是同一套编辑器，交互一致。
- **小屏卡片**是编辑器上的开关（默认关）：开启后当前节点居中成卡片；左/右滑使卡片只显示一半，空出的半屏列出这一侧的连接，点一条即打开相连的下一张卡片。细则与验收见 [docs/UX.md](../docs/UX.md)。
- 卡片模式与画布读写同一张图。支线 / 对白详情用列表或表单；节点图只服务主线骨架。

## MVP 成功标准（闭环）

见下文「MVP 定义」；验收上至少同时打通：

1. **创作路径**：新建项目 → Preset/Background/角色 → Main 节点骨架 → 若干 Beats → AI 文案辅助 +（生图或导入）挂图 → 双模式可玩 → 存读档  
2. **游玩路径**：导入现成项目包 → 不经创作即可双模式游玩 → 存读档  

## 待决（不阻塞文档收敛）

- 世界书：仅 Background 文本块，或最小「可检索条目」——见 Core，标记待定。
- 聊天「章节内有限自由聊」的幅度（默认：挂在当前章节/场景下续写）。
- MVP 生图：先支持一种主流 API 形态，还是抽象多提供商——实现时再定，产品要求是「可配置生图为主」。

---

## MVP 定义与范围

**MVP = 能让目标用户完整走通「创作一条短主线并玩到结局 / 或导入别人的短主线直接玩」的最小产品**，而不是功能清单缩略版。

### 必须有（建议纳入第一版可发布）

| 块 | 最小形态 |
| --- | --- |
| 项目 | 新建、打开、本地导出/导入包 |
| Preset | 一套可编辑的文风/禁用/偏好，生成与续写生效 |
| Background / Cast | 文本设定 + 角色；ST 卡选择性摘取 |
| Main 节点编辑 | 全端同一套节点编辑器（增删、连线、选中）；另有小屏卡片开关，验收见 UX |
| Beat | 对白、选项跳转、场景/立绘资源槽 |
| AI 文 | 若干固定动作（大纲、拆节点、写对白、润色）+ API 配置 |
| AI 图 | 至少一种可配置生图 + 结果入库；同时支持本地选图导入 |
| 运行时 | VN + 聊天双模式；存读档 |
| 纯玩 | 导入包后可只进运行时 |

### 明确推迟（有了也不算 MVP 失败条件）

- 完整世界书引擎、云同步/商店、ST 预设/正则兼容
- 节点编辑的高级能力（自动布局算法、小地图复杂交互、多人协作）
- 多生图提供商全家桶、批量出图工作流、Live2D
- 支线定式市场、精致演出时间轴

### 难点（按风险）

1. **节点编辑器与小屏卡片**  
   全端必须是同一套真节点编辑器（含平板），不能在手机上换成另一套。小屏再加可选卡片：半张卡 + 半屏连接，点连接跳到下一张。难点是两种呈现共用一张图，以及横滑不要和系统返回抢手势。按 [docs/UX.md](../docs/UX.md) 的 A/B 验收。

2. **一份内容、两种播放 + 创作/游玩对等**  
   Beat 模型既要撑 VN 舞台，又要撑聊天续写；导入包还要让纯玩家零创作可玩。状态机、存档字段、资源路径一旦设计飘，后面两套 UI 会分叉。难点在领域模型收敛，不在多画几个页面。

3. **AI 文/图接入的稳定性与可替换**  
   用户自备 API，失败、限流、格式漂移是常态。动作要结构化输出（便于写回节点/Beat），生图要异步、可重试、可改提示词再生成，并与「本地导入」共用资源槽。难点在产品容错与基础设施抽象，而非「调通一次 API」。

4. **Main 节点 vs Beat 粒度**  
   节点若太细会变成对白流程图（移动端必死）；太粗又只剩章节列表。需要约定：节点 = 情节单元/场景块，Beat = 单元内可播放句段。定不清会同时坑编辑器与运行时。

5. **范围膨胀**  
   「参考酒馆」容易滑向预设/世界书/插件；「节点编辑器」容易滑向完整蓝图 IDE；「AI 生图」容易滑向素材管线。MVP 要用上表「必须有 / 推迟」做砍刀，否则跨平台一致 UI 会拖死首发。
